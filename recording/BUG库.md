> 只记**真踩过**的，全部是"零报错"型 —— 不报错、不告警，只是结果不对。
> 编号 `RC-xxx`（Record Capture）。新条目往下加。

## RC-001 · 渲染器绕过页面 vmap，视频整体错位 2.08 秒 ★★★

| 项 | 内容 |
|---|---|
| 日期 | 2026-10-21 |
| 现象 | 录屏美化页的红框看着"歪"。查下来**框没歪**，是**画面相对旁白整体提前**了 |
| 根因 | `render-record.cjs` 在 `renderAsync(t)` 之后**又写了一遍 `v.currentTime = t`**。页面自己的 `vmap` 形同虚设：R01 是 `0.779t + 2.077`，正确值比 `t` 大最多 **2.08s** |
| 为什么没被发现 | ① `safe_check` / `density_check` 都不管视频时间；② 页面注释里写着"逐帧同时驱动 render(t) 与 currentTime"，看着像有意为之；③ **在 t≈9.4 处 `vmap(t) ≈ t`**（解 `t = 0.779t+2.077`），抽那一帧检查完全正常 |
| 修法 | `renderAsync` 存在时**直接 return**，不许再碰 currentTime；旧页面走 `window.vmap(t)` 并等 `seeked` |
| 判据 | `anno_check.cjs` **A1**：`\|vCur − vmap\| ≤ 0.02s` |
| 教训 | **"看着对"可能只是抽到了不动点。** 验证时间映射要在**差最大的时刻**抽，不是随便抽一帧 |

## RC-002 · 等 60ms 就截图，seek 没完成 → 偶发取到上一帧 ★★

| 项 | 内容 |
|---|---|
| 日期 | 2026-10-21 |
| 现象 | 同一页重渲两次，个别帧和相邻帧"串了"，红框和内容差一截 |
| 根因 | 固定 `sleep(60)`。4K 下 seek 偶发 >60ms，截图拿到的是上一帧 |

| 教训 | **固定等待 = 赌**。物理量（seek 完成）就该等事件，不该等时长 |

## RC-013 · CDP 读到了「另一个窗口」的视口，坐标全错 ★★★

| 项 | 内容 |
|---|---|
| 日期 | 2026-10-22 |
| 现象 | `cdp_probe` 报 `innerWidth=3440`，而正在录的窗口明明是 1920×1080 |
| 根因 | VS Code 同时开了两个窗口。`browser.pages()` 返回**所有窗口的 renderer**，脚本挑了第一个有 `.monaco-workbench` 的 —— 那是**另一个已最小化的 3440 窗口** |
| 为什么难发现 | 读数本身合法（3440 是真实存在的窗口宽度），元素矩形也"合理"，只是**不是这个窗口的** |
| 修法 | 遍历所有 page，按 `innerWidth` 与目标窗口宽度的差值挑最小的那个 |
| 教训 | **多窗口应用的 CDP 是"全进程"视图，不是"当前窗口"视图。** 拿到视口尺寸先跟 Win32 的窗口 rect 对一次，对不上就是读错了 |

## RC-014 · 剪贴板被第三方程序随时改写，粘出来是别人的商品名 ★★★

| 项 | 内容 |
|---|---|
| 日期 | 2026-10-22 |
| 现象 | 录制脚本 Ctrl+V 粘贴 `esp-idf`，实际粘进去的是「某个电商商品名」——需求方剪贴板里当时存着的东西 |
| 根因 | 本机常驻程序会改写剪贴板。"开录前设一次"到真正 Ctrl+V 之间隔了十几秒，够被改三次 |
| 修法 | `auto_record.py` 内置 `{"do":"clip","text":"..."}` 动作，用 Win32 `OpenClipboard/EmptyClipboard/SetClipboardData` 直接写，**放在 Ctrl+V 前 0.05 秒** |
| 二次坑 | 64 位 Python 下 `GlobalAlloc/GlobalLock` 不声明 `restype` 会被按 `c_int` 收 ⇒ 句柄截断成 0 ⇒ `memmove` 写地址 0 ⇒ `access violation writing 0x0` |
| 教训 | **剪贴板是共享可变状态，不是你的变量。** 要用它的那一刻再写，写完立刻用 |

## RC-015 · `anno-kit.tick()` 丢掉 `draw()` 返回值 → 过 t1 的标注件不消失 ★★★

| 项 | 内容 |
|---|---|
| 日期 | 2026-10-22 |
| 现象 | 一屏同时亮起 2–3 个红框，最后一个跑到画面外 |
| 根因 | `tick(t)` 写成 `if (items[i].draw(t)) any = true;` —— **返回值只用来汇总，没人据此隐藏元素**；而各件的 `draw` 又只按 `t0` 算动画进度、**不判 `t1` 之后该不该出现** |
| 修法 | `const on = draw(t); if (!on) el.style.opacity='0';` |
| 教训 | **"返回值没人用"是最隐蔽的死代码。** 一个函数返回布尔却不被消费，等于那半个契约不存在 |

## RC-016 · 页面只引了 `anno-kit.js`，忘了引 `anno-kit.css` ★★

| 项 | 内容 |
|---|---|
| 日期 | 2026-10-22 |
| 现象 | 所有标注件堆在左上角、按文档流竖排；红框宽度却是对的 |
| 根因 | 缺 `<link rel="stylesheet" href="...anno-kit.css">` ⇒ `.ak{position:absolute}` 没生效 ⇒ `left/top` 被当成 static 元素的无效属性忽略；但 `width/height` 是 inline style，照样生效 ⇒ **"尺寸对、位置全堆在原点"** |
| 为什么难发现 | JS 加载成功、`ANNO.init()` 不报错、`opacity` 读到 0.95，一切"正常" |
| 教训 | **一个组件是 JS + CSS 两份文件时，先确认两份都在。** "能跑但位置不对"高度怀疑样式没进来 |

## RC-019 · 522 帧 4K 渲染被 2 分钟默认超时腰斩，且不能续 ★★★

| 项 | 内容 |
|---|---|
| 日期 | 2026-10-22 |
| 现象 | 渲染跑到第 395/522 帧进程消失，成片没更新；日志被 `tail -6` 吞掉，看起来"零输出" |
| 根因 | 后台任务用默认 120s 超时，而 4K 每帧约 250ms × 522 ≈ 130s；且渲染器一上来就 `rm -rf` 帧目录 + `-i f%04d.jpg` 硬要求从 0 连续 |
| 修法 | ① 渲染器加**断点续渲**：按「页面文件 size+mtime+时长」做指纹存 `_meta.json`，指纹一致就从已有帧数接着渲，不一致才清空；② 调用时显式给长超时 |
| 实现二次坑 | ① `path.resolve(pf)` 写在 `const [pf,qs]=page.split('?')` **之前** ⇒ `Cannot access 'pf' before initialization`；② 帧数用 `Math.round` ⇒ 17.376s 只得 521 帧 = 17.3667s，**比配音短 9ms**，应该 `Math.ceil` |
| 教训 | **长任务必须有断点和指纹。** 没有指纹的续渲会把"改了页面"和"没渲完"混成一条错片 |

## RC-020 · 用「被缩放过的截图」估读坐标，越改越偏 ★★★

| 项 | 内容 |
|---|---|
| 日期 | 2026-10-22 |
| 现象 | R15 语言菜单的白框，最早写 `(1146,68,77,58)`（≈对），我"修正"成 `(1111,58,58,46)`，结果框跑到菜单左上角的空白里；最后用网格量出真实值 `(1145,66)-(1225,128)` —— **等于绕一圈回到原点** |
| 根因 | 我裁了一张 `1520×800` 的图去看，`Read` 把它**缩放**到约 1080 宽再显示。我拿显示图的比例换算回原图，等于把 1.4 倍缩放当成了 1:1 ⇒ 每个读数都乘错系数 |
| 为什么难发现 | 缩放后的图**看起来很正常**（没有黑边、没有提示），文字也读得清；换算出来的数还在合理范围内，不会触发任何断言 |
| 修法 | ① 裁图输出宽度 **≤900**（此尺寸下 Read 不缩放）；② 用 `drawgrid` 叠网格，**让每一格等于已知的原图像素数**（例：`crop=300:120 + scale=900:360 + drawgrid=w=30:h=30` ⇒ 每格 = 原 10px），直接数格子，不做比例换算 |
| 教训 | **任何"看图数像素"的结论，前提是先确认图有没有被缩放。** 网格锚定比比例换算可靠 —— 网格把"比例"这件事变成"数格子"，不需要相信任何缩放系数 |
| 同族 | 与「判据自己会错」是一类：**测量工具本身没校准，读数再精确也是错的** |
