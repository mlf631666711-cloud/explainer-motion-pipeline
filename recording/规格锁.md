# 自动录屏工具 · 规格锁

> 本文件管**录**与**标**两件事。版本 v1.0（2026-10-21 立）。
> 冲突时：**本文 > 各下游项目的版式偏好**；下游更严的以更严为准（写清楚在哪）。

---

## §1 录制口径（硬参数）

| 项 | 值 | 说明 |
|---|---|---|
| 画面 | **1920×1080 / 30fps** | 与下游 4K 成片同比例；**4K 由下游放大，录制不录 4K** |
| 区域 | **必须显式给** `--region 0,0,1920,1080` | 不给就录整块桌面（本机 3440×1440），产物直接废 |
| 编码 | `libx264 / veryfast / crf 18 / yuv420p` | 中间素材，不用高质量档 |
| 单条时长 | **10–15 秒**，上限 20 秒 | 长了必有一段不能用；也更容易撞弹窗 |
| 产物 | `rNN-*.mp4` 原始素材，**只读** | 后续美化页引用它，不许改 |

### §1.1 三条前置（缺一条整批废）

1. **窗口必须最前**。`gdigrab` 抓的是桌面合成结果 —— 窗口在后面就录到别的程序。
   网页侧 `web_drive.cjs` 的 `bringToFront()` 已内置；原生应用**每次操作前都要重新 `focus()`**。
2. **通知必须关**。`record_mode.ps1 -Action on` → 录完立刻 `off`，写在 `finally` 里。
3. **开录前清残留**。成功那次留下的 Chrome 会占调试端口，表现为 `_drive.log` **全空**、
   只报"60s 没就绪"。`rec_web.py` 已内置 `kill_stale_chrome()`（只杀带 `--remote-debugging` 的根进程）。

### §1.2 网页 vs 原生

| | 网页 | 原生应用 |
|---|---|---|
| 坐标来源 | **DOM `getBoundingClientRect()`**，精确到 px | 截图量，误差 ±20px |
| 驱动 | `web_drive.cjs`（红标自校准视口原点） | `auto_record.py` + `mouse.py` |
| 打字 | `type_text()` 逐字 | **必须用剪贴板 + Ctrl+V**（本机有全局输入钩子，见 BUG RC-011） |
| 失败形态 | 选择器过期 ⇒ found=false（可判） | **点空不报错**（不可判，只能靠截图复核） |

## §2 标注件：五种，各有各的活

> 需求方 2026-10-21：「标重这里多使用几个 红框除外 可以使用荧光笔 下划线 箭头 毛玻璃框来展示」。
> 实现在 `工具/anno-kit.js` + `anno-kit.css`，坐标一律用**视频坐标**（1920×1080 那套）。

### §2.1 分工表（选错就等于没说清）

| 件 | 干什么用 | 什么时候用 | 每屏上限 | 入场 |
|---|---|---|---|---|
| **① 红框** | 点明**操作目标** | 按钮 / 输入框 / 菜单项 —— "点这里" | **1** | 0.32s 缩放进 + 微弹 |
| **② 荧光笔** | 强调**文字或数值** | 一句话、一个数字要记住 | **1** | 从左侧刷过（宽度生长） |
| **③ 下划线** | 与荧光笔**二选一** | 逐字念到、逐步成立 | **1** | 同理，但更轻 |
| **④ 箭头** | 指向**小目标**或**方向** | 红框会糊住的小图标 / 表示"往下走""往左移" | 1–2 | 线先长，箭头后到（末 15%） |
| **⑤ 毛玻璃框** | 给区域**打底**让字读得清 | 花底白字 / 需要压住背景 | 1 | 0.40s 淡入 + 标签延后 0.25s |

### §2.2 五条禁令

1. **一屏强调位 ≤2**（红框 1 + 荧光笔/下划线 1）。箭头与毛玻璃**不算强调位**，但也不许当装饰撒。
2. **同一目标不许叠两种** —— 红框 + 箭头指同一个按钮 = 啰嗦；选一个。
3. **毛玻璃必须有底衬作用**：它下面得真有"看不清的内容"。压在纯色背景上 = 装饰，删掉。
4. **箭头不许穿字**。指向文字类目标时，箭头端点停在字外 ≥8px。
5. **不许跨出取景框**。越界会被 `#win` 的 `overflow:hidden` 切掉一条边 —— 这是"看着歪"的常见假象。

### §2.3 时间口径

- 每个标注件的窗口 = **它服务的那句配音的时长**，不是固定值。
- 入场动作 **0.32–0.55s**；出场**直接消失**或 0.2s 淡出，**不做退场动画**（抢注意力）。
- 两个标注件**不许同时入场**（差 ≥0.25s），否则观众不知道先看哪个。

## §3 坐标怎么来（不许目测）

**唯一合法来源：`box_finder.cjs`。**

```bash
# 1) 先出静帧，看清目标在屏幕上的位置
node stills.cjs <页面.html> 6.0,12.0 _gate/x

# 2) 给一个落在目标上的点，工具反解出精确矩形（并直接给出 B(...) 形参）
node box_finder.cjs <页面.html> 6.0 786,318 --tol 28 --pad 6
#    → 屏幕矩形 [756,296 316x72]
#    → ★ 贴进页面：B(674.7,421.7,444.2,101.2)
```

**为什么禁目测**：看 1080 宽的预览图再乘 1.7778，误差 ±20px；框一旦偏出目标边缘，
观众读到的是"框画错了"，而不是"这里有个东西"。

## §4 闸门 `anno_check.cjs`（录完/标完必须过）

```bash
node anno_check.cjs <页面.html>            # 自动按 window.BOX 的窗口采样，每框 2 点
node anno_check.cjs <页面.html> --neg 40   # 负控：把标注件真挪 40px，**必须变红**
```

| 判据 | 线 | 抓什么 |
|---|---|---|
| **A1 时间对齐** | \|vCur − vmap\| ≤ **0.02s** | ★ 抓"渲染器绕过 vmap"，R01 曾因此错位 2.08s |
| **A2 在画幅内** | 越界 ≤ 1px | 框被 `overflow:hidden` 切边 |
| **A3 尺寸** | 占画幅 0.05%–30%；线状件只查退化 | 框贴满整屏 / 退化成一条 |
| **A4 压在内容上** | 框心梯度 ≥ **1.6** | 框画在空处（白框）· **只判红框** |
| **A5 边框已画** | 信号红像素 ≥ **55%** | 框没渲染出来 / 被内容盖住 · **只判红框** |
| **A6 可见** | opacity ≥ 0.85 | 时间窗写错，这时早该消失 |

**阈值全部实测**（2026-10-21）：
- `emptyE 1.6` —— 自检页框心实测 3.1–5.4，空场 0.0–0.8，取中间偏下；
- `borderRatio 0.55` —— 正常框实测 0.97–1.00，负控挪走实测 0.00；
- `areaWarn 0.25%` —— R09 的扩展图标只有 0.10%，4K 下才 74×62，给 WARN 不给 FAIL。

**三条使用纪律**：
1. **`--neg` 不红 = 判据没牙**，先修判据，别改片子。
2. 闸门只判机械错，**判不了"好不好看"** —— 好不好看得 `--shot` 出图后肉眼过。
3. **毛玻璃不参与 A4**：`backdrop-filter` 会把梯度抹平（实测 1.36），那是它的正常行为。

## §5 与下游的分工

| 谁 | 管什么 |
|---|---|
| **本项目** | 录原始片段 + 标注件库 + 标注重闸 |
| 下游（如 `15-ESP32教程`） | 把片段放进美化页：取景框 / 运镜 / 右栏卡片 / 排版 |

> 下游**不要自己写标注件**，直接用 `anno-kit.js`；也不要把坐标手填进去，用 `box_finder`。
